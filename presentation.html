Methodology — 7-Phase OODA Hunt Loop

1

Hypothesize

Gemini generates 3–5 ranked hypotheses mapped to MITRE ATT&CK tactics & techniques

2

Plan Queries

LLM writes platform-specific queries (KQL, SPL, FQL) — each passes safety validation

3

Approval Gate

Human analyst reviews & approves/rejects — RBAC enforced (approver/admin only)

4

Execute Queries

Approved queries dispatched to EDR / SIEM / Intel via integration dispatcher

5

Analyze Evidence

LLM classifies evidence (confirming/contradicting/neutral), extracts IOCs, assigns confidence 0–100

6

Loop Decision

Confidence < 70% & iterations < 5 → loop back to Phase 2. IR escalation if critical threat found.

7

Report Generation

Structured report (PDF / JSON / MD) with executive summary, IOC list, timeline, MITRE mapping

OODA Loop: Observe → Orient → Decide → Act. The hunt iterates until confidence threshold is met or max iterations reached.

Security & Safety Design

Every layer of ShadowHound is designed with security-first principles

🛡️ Query Safety Validation

Regex-based blocklist prevents destructive operations before queries reach the approval gate

BLOCKED_PATTERNS = [
  "drop", "delete", "truncate",
  "insert", "update", "exec"
]
SPL_BLOCKED = [
  "| outputlookup", "| collect",
  "| sendemail", "| script"
]
KQL: "| invoke" → BLOCKED

🔐 Authentication & RBAC

JWT-based auth with three-tier role hierarchy

analystCreate hunts, view own hunts
approver+ Approve/reject queries
admin+ User mgmt + audit logs

📜 Immutable Audit Log

Every action logged with user identity, timestamp, payload hash, IP address, and user agent. Append-only — no edits or deletions allowed.

🧬 LLM Safety

  • Structured JSON schemas constrain output
  • External data in separate message fields (anti prompt-injection)
  • Safety validator runs after LLM output
  • No raw security data persisted
